 # Agent Memory

 会話をまたいで知識を保存するための永続メモリスペース。

 **場所:** `.claude/skills/agent-memory/memories/`

 ## 積極的な活用

 以下のような場合にメモリを保存する：
 - 調査に手間がかかった調査結果
 - コードベースの非自明なパターンや落とし穴
 - トリッキーな問題の解決策
 - アーキテクチャの決定とその根拠
 - 後で再開する可能性がある作業中の内容

 以下のような場合に既存メモリを確認する：
 - 問題のある箇所を調査し始める前
 - 過去に触れたことのある機能を作業するとき
 - 会話の中断後に作業を再開するとき

 以下のような場合にメモリを整理する：
 - 同じトピックに散らばったメモリを統合する
 - 古くなった・置き換えられた情報を削除する
 - 作業が完了・ブロック・破棄されたときに `status` フィールドを更新する

 ## フォルダ構成

 ガイドライン:

 - ディレクトリは作らずフラットにファイル作成する
 - ファイル名は `%Y%m%dT%H%M%S--description.md` 形式にする（例: `20251008T013000--aws.md`）
 - 知識ベースの進化に合わせて統合・再整理する

 ## フロントマター

 すべてのメモリファイルには `summary` フィールドを含むフロントマターが必要。サマリーは内容全体を読む必要があるかどうかを判断できる程度に簡潔に書く。

 **サマリーは判断のポイント**: エージェントは `rg "^summary:"` でサマリーをスキャンして、どのメモリを詳しく読むか判断する。この判断に十分な情報（何に関するメモリか、主な問題やトピック、重要な理由）を含めて書くこと。

 **必須:**
 ```yaml
 ---
 summary: "このメモリが含む内容の1〜2行の説明"
 created: 2025-01-15  # YYYY-MM-DD 形式
 ---
 ```

 **任意:**
 ```yaml
 ---
 summary: "大容量ファイル処理中のワーカースレッドメモリリーク - 原因と解決策"
 created: 2025-01-15
 updated: 2025-01-20
 status: in-progress  # in-progress | resolved | blocked | abandoned
 tags: [performance, worker, memory-leak]
 related: [src/core/file/fileProcessor.ts]
 ---
 ```

 ## 検索ワークフロー

 サマリー優先のアプローチで効率的に関連メモリを探す：

 ```bash
 # 1. カテゴリ一覧を確認
 ls ~/Project/q/

 # 2. すべてのサマリーを表示
 rg "^summary:" ~/Project/q/ --no-ignore --hidden

 # 3. キーワードでサマリーを検索
 rg "^summary:.*keyword" ~/Project/q/ --no-ignore --hidden -i

 # 4. タグで検索
 rg "^tags:.*keyword" ~/Project/q/ --no-ignore --hidden -i

 # 5. 全文検索（サマリー検索では不十分な場合）
 rg "keyword" ~/Project/q/ --no-ignore --hidden -i

 # 6. 関連するメモリファイルを読む
 ```

 ## 操作

 ### 保存

 1. 内容に適したカテゴリを決める
 2. 必須フロントマターを含めてファイルを書く（現在日付は `date +"%Y%m%dT%H%M%S"` で取得）

 ```bash
 mkdir -p ~/Project/q
 # ファイル名は $(date +"%Y%m%dT%H%M%S")--description.md 形式
 cat > ~/Project/q/$(date +"%Y%m%dT%H%M%S")--description.md << 'EOF'
 ---
 summary: "このメモリの簡潔な説明"
 created: 2025-01-15
 ---

 # タイトル

 内容をここに...
 EOF
 ```

 ### 保守

 - **更新**: 情報が変わった場合は内容を更新し、フロントマターに `updated` フィールドを追加する
 - **削除**: 不要になったメモリは削除する
   ```bash
   trash ~/Project/q/category-name/filename.md
   # 空のカテゴリフォルダも削除
   rmdir ~/Project/q/category-name/ 2>/dev/null || true
   ```
 - **統合**: 関連するメモリが増えてきたらマージする
 - **再整理**: 知識ベースの進化に合わせて適切なカテゴリへ移動する

 ## ガイドライン

 1. **再開を想定して書く**: メモリは後で作業を再開するために存在する。コンテキストを失わずに続けるために必要なすべての要点（決定事項、その理由、現在の状態、次のステップ）を記録すること。
 2. **自己完結したノートを書く**: 読者が事前知識なしに内容を理解して行動できるよう、完全なコンテキストを含める。
 3. **サマリーを判断可能に保つ**: サマリーを読めば詳細を読む必要があるかどうかがわかるようにする。
 4. **最新に保つ**: 古くなった情報は更新または削除する。
 5. **実用的に**: 実際に役立つものだけを保存し、すべてを保存しない。

 ## 記載内容の参考

 詳細なメモリを書くときは以下を含めることを検討する：
 - **コンテキスト**: 目的、背景、制約
 - **状態**: 完了・進行中・ブロック中の内容
 - **詳細**: 主要ファイル、コマンド、コードスニペット
 - **次のステップ**: 次にやること、未解決の疑問

 すべてのメモリにすべてのセクションが必要なわけではない。関連するものを使うこと。
